买主机游戏和实体卡带久了，常常会有两个错觉：一是觉得自己买得不多，二是总高估某张卡“玩完出掉应该没亏多少”。

之前试过用现成表格或通用记账 App 记，但很快会遇到几个别扭的地方：港服、日服、美服、国行跨区币种混杂；买盘时的邮费、出二手时的平台手续费和快递费不算进去，永远是笔糊涂账；充值点卡如果和数字版购买同时记一笔，支出会直接算重两次。

于是干脆自己用 React 18 + TypeScript Strict 写了一个开源的主机游戏与硬件账本——**[psn-ns-record](https://github.com/CodeAlex52/psn-ns-record)**（MIT 协议，在线版本直接托管在 [psn-ns-record.664501775.workers.dev](https://psn-ns-record.664501775.workers.dev)）。

## 一、为什么要做成 100% 离线、零后端架构

记游戏购买记录和玩游戏的心情，是非常私人的账本——根本没必要为此搭一套账号体系、租数据库或者把消费流水传到别人的服务器上。

整套应用没有后端、没有登录弹窗，只是一包部署在静态边缘节点的 PWA（Vite + React Router 6）：

- **浏览器原生的 IndexedDB 事务封装**：自己包了一层基于原生 IndexedDB 的事务读写模块，不依赖沉重的第三方 ORM，几十上千条卡带和流水在本地毫秒级读写、离线一样打开即用。
- **随时能全量带走的数据主权**：集成 SheetJS（`xlsx`）和 PapaParse，随时导出完整 Excel、JSON 或 CSV 备份，也能直接把旧表格导进来。哪怕哪天不想用这个工具了，你的全部记录也不会被锁死在某个云服务格式里。

## 二、游戏人的真实账本，和普通记账哪里不一样

写这个工具时，最花心思的不是 UI，而是把“买盘—通关—回血—买点卡—添置机器”这整套领域模型算准：

### 1. 二手卡带的真实回血盈亏

实体盘卖出去不是“标价减买入价”那么简单。账本把二手流通的真实损耗全部摊开算清楚：

```text
实际到手 = 卖出标价 - 平台手续费 - 快递费
最终盈亏 = 实际到手 - 买入成本
净单小时成本 = max(0, 买入成本 - 实际到手) / 游玩小时数
```

很多看起来很保值的第一方大作，算上手续费和两次邮费之后，到底花了多少钱、按实际游玩时间折合每小时多少块钱，一眼就能看明白。

### 2. 游戏、硬件与点卡“三本分账”

- **游戏账本**：记录单款作品从 **购入 → 游玩中 → 通关 / 弃坑 → 出掉** 的完整生命周期时间线，同时记录主观打分（**1–5 分愉悦度**与 **1–10 分综合评分**），支持 `CNY / HKD / JPY / USD` 多币种核算。
- **硬件与外设账本**：PS5、NS2、手柄、底座单独归档，不混进单款游戏的成本统计里。
- **点卡 / 充值卡独立账本**：先买折价点卡充值进账户、再拿账户余额买数字版，这两笔流水分开对账，避免总消费统计虚高翻倍。

> 技术选型上用的也是最朴实的一套：React 18、严格模式 TypeScript、Vite PWA、Lucide React 图标加上原生的 IndexedDB。

一个顺手的小工具，能让你在双十一或者打折季准备“再买一张”之前低头看一眼：积灰率是多少，上个月平均每小时玩游戏花了多少钱，手里还有多少坑没填。看清数字之后，剁手反而冷静不少。
